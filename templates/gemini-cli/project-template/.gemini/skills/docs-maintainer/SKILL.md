# 文档维护技能

## 核心原则
1. 事实优先：所有内容必须来自真实代码。先读代码，再写文档；宁可标注
   「待确认」，不要编造。
2. 规范优先：动手前先读 `docs/README.md`（写作规范与索引）和根 `GEMINI.md`
   （文档同步要求）。
3. 最小改动：更新时只改与现状不符的部分，保留原有结构与风格，不做大重排。

## 工作流
1. 判断任务类型：新建文档 / 代码变更同步 / 定期审计。
2. 新建：按 `docs/README.md` 的三要素（读者、用途、更新触发条件）起草，
   在索引登记。
3. 同步：用 `git log` / `git diff` 找到改动 → 按「更新触发条件」锁定受影响
   文档 → 逐项核对 → 只改偏差处。
4. 审计：按 `references/doc-checklist.md` 逐项检查，输出分级报告
   （事实错误 / 缺失 / 建议），标注文档位置与代码位置。
5. 结束后检查根 `GEMINI.md`「按需查阅」表是否需要同步更新。

## 边界
- 不为了让文档自洽去改代码；发现代码问题单独报告。
- 不猜测未定义的约定；需要决策时停下来询问。
