# 错误码规范与码表

> 读者：所有写业务代码的人与 AI。**任何涉及错误码的任务都必须先读本文件。**
> 用途：统一错误码的取号、命名、登记方式，避免冲突与重复。
> 更新触发条件：任何错误码的新增 / 修改 / 废弃。

## 规范

### 码段划分

> 示例仅作演示，按你项目的模块实际情况调整；原则是「一模块一段，永不混用」。

| 码段 | 模块 | 占用情况 |
| --- | --- | --- |
| 1000–1999 | 通用 / 框架层 | 1001–1003 已用 |
| 2000–2999 | 用户与认证 | 空 |
| 3000–3999 | 数据与存储 | 空 |
| 9000–9999 | 预留（不得占用） | — |

### 命名规则

- 格式：`E<四位编号>`，如 `E1001`
- 常量名：`ERR_<模块>_<含义>`，如 `ERR_AUTH_TOKEN_EXPIRED`
- 含义一句话说清「发生了什么」；触发场景写「什么条件下会抛」

### 新增流程

1. 确认所属模块 → 找到对应码段。
2. 取码段内下一个可用编号（查下方码表，**不跳号、不复用废弃号**）。
3. 在代码中按现有写法定义（找到定义错误码的源文件保持一致）。
4. 在下方「全量码表」登记。
5. 码段已满 → 停下来询问，不要擅自开新段。

### 禁止事项

- 禁止临时编造未登记的码
- 禁止复用其他模块码段的编号
- 禁止复用已废弃的编号（废弃号标记后永久保留）
