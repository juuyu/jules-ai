# 编码规范与工具类清单

> 读者：所有写代码的人与 AI（写新代码、评审前先读）。
> 用途：统一代码风格，明确「哪些轮子已经有现成的」。
> 更新触发条件：规范调整、新增 / 移除工具类、命名约定变化。

## 编码规范

| 主题 | 约定 |
| --- | --- |
| 格式化 | <如：Prettier / gofmt，提交前必须执行> |
| 命名 | <如：文件用 kebab-case，类型用 PascalCase，常量全大写> |
| 导入顺序 | <如：标准库 → 第三方 → 本项目> |
| 错误处理 | 统一使用 `docs/error-codes.md` 中的错误码，禁止裸抛字符串 |
| 日志 | <如：统一用 logger 工具，禁止 console.log> |
| 注释 | 只在「为什么」不明显时写，禁止复述代码 |

## 工具类清单（先查再写，禁止重复实现）

| 工具类 / 函数 | 位置 | 用途 | 备注 |
| --- | --- | --- | --- |
| <日期工具> | `src/utils/date.ts` | <...> | |
| <校验工具> | `src/utils/validate.ts` | <...> | |
| <HTTP 封装> | `src/utils/http.ts` | <...> | |

> 维护提示：工具目录也可按「就近原则」在目录内放一个 `GEMINI.md`，
> AI 读到该目录文件时会自动加载，比查表更及时。

## 提交规范

- 格式：Conventional Commits（`type(scope): subject`）
- `type` 取值：`feat` / `fix` / `docs` / `refactor` / `test` / `chore`
- 提交前必须通过：<lint / 测试命令>
