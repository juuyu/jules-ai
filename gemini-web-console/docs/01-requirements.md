# 需求文档

> 状态：初稿 v0.1（2026-10-15）｜关联：[技术方案](./02-technical-design.md)

## 1. 背景与动机

- 公司电脑**仅可使用 Gemini CLI**，无法安装 Code / Qoder 等 AI IDE
- 终端操作成本高：开终端、切目录、记命令，缺少工作区选择、按钮化操作等 IDE 式体验
- 希望收敛到**浏览器**完成日常 AI 开发：选工作区 → 跑会话 → 看变更 → 提交代码 → 管理配置

## 2. 目标与非目标

### 目标

| 编号 | 目标 |
| --- | --- |
| G1 | 在浏览器中使用 Gemini CLI，**体验与终端完全一致**（实时输出、颜色、交互式 TUI） |
| G2 | 高频操作面板化：工作区、Git、配置、MCP、Skills、会话导出 |
| G3 | 会话持久：刷新页面、关闭浏览器、断开重连都不丢进程与历史 |
| G4 | 纯本地运行，数据不出本机 |

### 非目标

- 不做完整 IDE（暂无代码编辑器、文件树编辑，后续按需再加）
- 不做多用户、远程/公网访问
- 不重写 Gemini CLI 的对话与工具执行逻辑，最大化复用 CLI 自身能力

## 3. 目标用户与使用场景

单用户（本机开发者本人）。典型场景：

1. 到公司开工：打开浏览器 → 选择工作区 → 打开终端跑 `gemini` → 多 tab 并行
2. 会话结束：一键导出会话记录（Markdown / JSON）
3. 改完代码：查看 `git status / diff` → 填写 commit message → 提交 → push
4. 新增 MCP server / Skill：面板中表单化添加，无需手改配置文件

## 4. 功能需求

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| FR-1 | 工作区管理 | 添加/切换工作区（=本地目录）、最近使用列表；每个工作区独立终端与会话上下文 | P0 |
| FR-2 | 终端会话 | 多 tab；实时输出；窗口自适应（resize 透传）；刷新/断连不丢进程；历史可回溯 | P0 |
| FR-3 | 配置查看与编辑 | 合并展示用户级与工作区级 `settings.json`，支持直接编辑保存 | P1 |
| FR-4 | Git 操作 | status 列表、diff 预览、commit（填 message）、push 按钮；操作前二次确认 | P1 |
| FR-5 | 会话浏览与导出 | 按工作区列出 Gemini 历史会话（读取 chats 目录），支持预览与导出 Markdown/JSON | P2 |
| FR-6 | MCP 管理 | 图形化增删改 `mcpServers`（用户级/工作区级），全局 `allowed / excluded` 开关 | P2 |
| FR-7 | Skills 管理 | 列表、查看、新建、编辑、启用/停用（用户级与工作区级） | P2 |
| FR-8 | 自定义命令管理 | 浏览/编辑 `commands/*.toml`（用户级与项目级，含命名空间） | P2 |
| FR-9 | 聊天式界面（探索） | 基于 headless `stream-json` 的对话式 UI、工具调用卡片 | P3 |
| FR-10 | 审批与模型控制（探索） | 基于 ACP 的细粒度审批、切换模型、会话控制 | P3 |

## 5. 非功能需求

| 编号 | 需求 |
| --- | --- |
| N1 | 终端保真：颜色、快捷键、TUI 程序（vim/htop）、进度条实时刷新均与原生终端一致 |
| N2 | 安全：仅监听 127.0.0.1 + 访问令牌；命令用参数数组执行，防注入；路径必须命中工作区白名单 |
| N3 | 性能：终端输出走 WebSocket 直通，低延迟；大输出不阻塞 UI |
| N4 | 部署：一条命令启动（如 `npm start`），无需额外基础设施 |
| N5 | 可维护：终端与各面板模块解耦，互不影响，便于逐个迭代 |

## 6. 约束与假设

- 公司电脑已有 Node.js 环境（Gemini CLI 本身基于 Node 运行）
- 仅本机访问，不暴露到公司网络之外
- Gemini CLI 升级可能调整内部文件格式/路径 → 面板读取需容错，关键路径以官方文档为准（见技术方案 §6）

## 7. 里程碑

| 阶段 | 内容 | 完成定义 |
| --- | --- | --- |
| P0 | 会话管理 + 工作区 + 终端多 tab | 浏览器里完整跑通 `gemini`，刷新不丢 |
| P1 | 配置查看 + Git 面板 | 常见日常操作不再需要打开终端 |
| P2 | 会话导出 + MCP / Skills / 命令管理 | 配置类需求全部图形化 |
| P3 | 聊天模式（stream-json）、ACP 探索 | 产品化增强，按需推进 |

## 8. MVP 验收标准（P0）

- [ ] 浏览器打开本地地址，看到工作区列表，可添加本机目录为工作区
- [ ] 选择工作区后创建终端，运行 `gemini` 与原生终端体验一致（颜色/交互/实时输出）
- [ ] 刷新页面或重开浏览器后，会话进程仍在，历史输出完整可见
- [ ] 多个终端 tab 互不干扰；页面/窗口缩放后，TUI 布局自动适配
