# 02 核心技能

> 本章解决：怎么把需求"说清楚"给 AI？怎么组织上下文让输出质量稳定？什么时候该用哪种协作模式？

## 2.1 面向代码任务的 Prompt 技巧

### 一条有效指令的四个要素

1. **目标**：要做什么，以及"做完的标志"（验收标准）
2. **上下文**：相关文件、接口签名、错误日志、现有约定
3. **约束**：不能动什么、性能 / 兼容性要求、风格要求
4. **期望输出**：改哪些文件、给 diff 还是完整文件、要不要先出方案

### 实用技巧

- **先规划再执行**：大任务先让它输出方案和步骤，确认后再动手（各工具普遍有 Plan 模式）
- **给例子胜过形容词**：贴一段现有代码，比说"风格保持一致"有效得多
- **一次一件事**：多个需求拆开问，比一次塞五个稳定
- **提供失败现场**：完整报错 + 复现步骤 + 环境信息，而不是一句"运行报错了"
- **要求验证方式**：让它给出测试或验证命令，别接受"已修复"的口头结论
- **允许它反问**：需求模糊时加一句"有任何不确定先问我"，比让它猜更好

### 常见反模式

| 反模式 | 问题 | 改进方向 |
| --- | --- | --- |
| "帮我优化一下这段代码" | 目标不明确，输出随机 | 说明维度：可读性 / 性能 / 内存 |
| 一次描述 5 个功能 | 注意力被稀释，漏改错改 | 拆成独立任务逐个提交 |
| 只贴代码不贴报错 | 只能靠猜定位原因 | 补全报错 + 复现步骤 + 环境 |
| "不对，再改改" | 缺少反馈信号 | 指出具体差异与期望结果 |

## 2.2 上下文工程（Context Engineering）

> 核心认知：模型输出的上限取决于上下文质量。同一个模型，上下文给得好坏，结果天差地别。

### 规则文件（项目级约定）

主流工具都支持"项目规则"文件，会话开始时自动加载：

| 工具 | 规则文件 |
| --- | --- |
| Claude Code | CLAUDE.md |
| Cursor | .cursor/rules/*.mdc |
| GitHub Copilot | .github/copilot-instructions.md |
| Windsurf | .windsurfrules / .windsurf/rules/ |
| 通用标准 | AGENTS.md（Codex、Jules 等越来越多工具支持） |

**规则文件写什么：**

- 技术栈与版本、目录结构说明
- 常用命令（构建 / 测试 / lint）
- 代码约定（命名、错误处理、提交信息格式）
- 禁忌（不要动某目录、不要引入新依赖）

**原则：短、具体、可验证。** 几百行的规则文件会被模型忽略；"用 pnpm 而非 npm"比"注意包管理器"有效。

### 主动供给上下文

- **引用文件**：用 @ 语法或拖拽把相关文件带进对话，别让 AI 猜
- **文档接入**：库的最新文档可通过 MCP（如 context7）实时拉取，解决"模型知识过时"
- **失败现场**：终端输出、失败测试、界面截图（多模态）都是高价值上下文
- **精确到行**：指明文件和函数名，减少它到处搜的成本

### 上下文管理

- **信噪比**：上下文窗口有限，塞入越多无关内容，有效信息占比越低
- **长会话要压缩**：接近上限时工具会自动或手动压缩（compaction）；重要结论让它写进文件而不是留在对话里
- **新任务开新会话**：旧话题的残留上下文会干扰新任务
- **交接文档**：会话结束前让 AI 总结"当前状态 + 下一步"，下个会话直接喂过去

### 常见错误

- ❌ 把整个项目都塞进上下文 → ✅ 只给相关文件
- ❌ 一个会话从早干到晚 → ✅ 按任务切分会话
- ❌ 规则文件写了从不更新 → ✅ 与代码同步维护

## 2.3 人机协作模式

四种基本模式，按"人的控制程度"从高到低：

| 模式 | 形态 | 适合场景 | 主要风险 |
| --- | --- | --- | --- |
| 补全 | 编辑器内 Tab 补全 | 熟练领域的重复代码 | 惯性接受，错过微妙错误 |
| 对话 | 聊天窗口问答 / 改代码 | 学习、探索、小修改 | 手动搬运代码的摩擦 |
| 委派 | Agent 自主多步执行 | 边界清晰的中大型任务 | 跑偏，需要仔细 review |
| 审查 | AI 审你的代码 / PR | 质量兜底 | 覆盖率与误报 |

### 什么时候切模式

- 不确定怎么做 → **对话**（先讨论方案）
- 确定怎么做且任务描述得清 → **委派**
- 关键路径代码 → 委派后必须人工审查
- 学习新领域 → 对话 + 让它解释每一步

### 心法

- **你负责方向与验收，AI 负责执行**：把精力花在定义问题和检查结果上
- **保持掌控感**：不理解就让它解释，不放心就先小范围试点
- **别交出自己的判断力**：AI 说"完成"不等于完成，代码跑通才算数
