# 01 基础认知

> 本章解决：AI 编程的底层原理是什么？能力边界在哪？模型怎么选？

## 1.1 LLM 工作原理速览

### 本质：下一个 token 预测器

- LLM 做的事：根据已有文本，预测下一个 token（词元），如此往复
- 代码对模型很"友好"：语法严格、模式重复，所以代码生成效果格外好
- "思考"也是生成：推理模型先输出思维链再给答案，本质仍是生成，但复杂任务效果显著提升

### 三个关键概念

- **Token**：文本的最小单元。中文约 1-2 字 / token，代码里符号和缩进同样占 token（计费也按它算）
- **上下文窗口**：模型一次能"看到"的内容上限（输入 + 输出），主流模型普遍 128k ~ 1M token
- **采样**：temperature 等参数控制随机性；写代码通常用低随机性，创意场景才调高

### 训练三阶段（理解"它为什么这样"）

1. **预训练**：从海量代码与文本中学习统计规律
2. **指令微调**：学会听指令、按格式回答
3. **对齐与强化学习**：变得更"有用"；推理模型在这一步加入长思维链训练

### 为什么会有幻觉

- 模型生成的是"最可能的文本"，不是"查证过的事实"
- 知识有截止日期：新版本 API、新框架用法是最容易编造的区域
- 应对：给它最新文档（MCP 实时拉取或直接粘贴）、要求它给依据、用编译器和测试把关

## 1.2 AI 编程的能力边界

### 擅长的（放心用）

- 样板代码、CRUD、配置文件、测试生成
- 正则、SQL、Shell 等"查语法"场景
- 解释陌生代码、跨语言翻译、写文档与提交信息
- 局部重构：提取函数、批量改名、拆分模块

### 需要警惕的（必须审）

- 跨几十个文件的大重构：它看不到全貌，还会"边改边忘"
- 并发、内存、性能等隐性正确性问题
- 最新 API / 冷门库：训练数据没覆盖，容易编造
- 需求中的隐性约束：你没说的，它默认不管
- 精确数学与数值计算

### 典型失败模式与防线

| 失败模式 | 表现 | 防线 |
| --- | --- | --- |
| API 幻觉 | 调用不存在的方法 / 参数 | 编译器、测试、让它先读官方文档 |
| 需求漂移 | 做多 / 做少 / 做偏 | spec 与验收标准（见 spec-coding） |
| 静默删改 | 顺手删掉"无关"代码 | 小步提交、逐 diff 审查 |
| 迎合式测试 | 测试写死只为通过 | 检查测试是否真的覆盖需求 |
| 过度自信 | "已修复""没问题" | 跑一遍才算数 |

## 1.3 模型选型（截至 2026-10）

| 家族 | 代表模型 | 特点 | 适合 |
| --- | --- | --- | --- |
| Anthropic Claude | Opus 5.5 / Sonnet 5.5 / Haiku 5.5 | 编程质量口碑最强，长程 Agent 稳 | 主力编程模型 |
| OpenAI GPT | GPT-6.1 Sol（上代 GPT-5.5） | Agent 与工具调用生态成熟 | 复杂 Agent 任务、通用 |
| Google Gemini | Gemini 4 "Argon"（2026-10 发布） | 百万 token 输出、定价激进 | 大代码库、成本敏感 |
| DeepSeek | V4.1-Flash 等 V4 系列 | 开源 + 极低价格 | 性价比首选 |
| 阿里 Qwen | Qwen3.8-Max 及开源系列 | 中文强、开源生态活跃 | 中文场景、本地部署 |
| Kimi / GLM / MiniMax | K3 / GLM-5.3 / M3 等 | 长上下文、中文优化 | 国内生态、尝鲜 |

> 版本迭代极快（几乎每月都有新版本），上表仅示意 2026-10 的格局，实际选型以官方发布与当期榜单为准。

### 怎么选

- **看榜单但不唯榜单**：SWE-bench Pro、Terminal-Bench、LMArena 都可参考（2026-10 头部模型 SWE-bench Pro 已接近 90%，彼此差距在缩小）
- **同一任务跑两个模型对比**：最可靠的选型方法，看体感差距而不是参数
- **成本策略**：主力模型 + 廉价模型组合——重任务用好模型，补全 / 摘要 / 批量任务用便宜模型
- **国内可用性**：DeepSeek / Qwen / Kimi / GLM 均提供 API 与订阅，合规与访问更友好

### 换模型的节奏

- 不要频繁换：工具链、提示词、习惯都会跟着变，迁移成本真实存在
- 出现明显的代际提升（榜单断层或体感差距明显）再迁移，一次只换一个变量
